# 设计哲学（Design Philosophy）

> **本文件是全 skill 的单一真相源。**
> 六件套、评分卡、校准回路、铸造者禁令——全部是下面六条公理的**推论**。
> 规则可以改，公理不能。遇到文档没覆盖的新情况，**回公理推导**，不要找最近的一条规则类比。

## 零、定位与表示法

### 零.1 这个 skill 只做一件事

> **从用户提供的信息里，铸出「一个人」的认知与思考模型。**

这个人**可以不存在**——真实人物、虚构角色、只存在于这次对话里的**合成人格**，三型共用同一条路径：
**提炼 → 显式公理集（可审计的根）→ 放大 → 完整认知 + 表达**。
**人格被 harness 触发即完成**：铸好、装进 `~/.claude/skills/` 之后，它怎么被用、和谁一起用，不是它的事。

**输入是通用的，且没有格式要求。** 用户给什么就读什么——粘贴文本、任意文件、任意目录、一份文献、
一部原作，或者干脆什么都不给（合成型）；**没有单独的输入契约文档**，材料怎么组织是用户的事。
材料侧的可选落盘约定（`MATERIAL.md` 布局、漂移检测怎么开启）见 `roster-format.md` §一。

### 零.2 为什么「公理集 + 推导闭包」是可行的表示法

本 skill 的赌注是：**一个人可以被表示成一份很小的显式公理集，加上一套有限的推导规则。**
这不是「概括」，是**压缩**：

| | **压缩** | **解压** |
|---|---|---|
| 是什么 | 从材料里找出**最小生成元**（3-7 条不可再分的基本立场） | 用生成元 + 闭包规则，推出这个人对**新情境**的判断 |
| 谁在做 | P2 提炼 → P3 立公理集 | P4 放大 |
| 成功的判据 | **重构测试**：用公理集能重推回材料里已有的判断 | **生成力探针**：能推出公理集里没写过的判断 |
| 失败的样子 | 公理集漏了东西 → 推不回材料里的判断 | 只会复述公理集 → **一本索引** |

**为什么值得用**：它把「模仿一个人」换成一件**可争辩**的事——每条判断都是「他立场的最小生成元」，
**可被追问、复现、挑战**。

> **可审计性，不是真值。** 四轴质检保证「每条判断**可被追问**」，不保证「判断是对的」——后者靠材料与
> 用户。**S = 0 判 D 的理由不是「这是假的」，而是「这不可追问」**；两者处置一致（都要回炉），
> 但说清是哪一个，才不会把「我核不出来」误判成「他在编造」（`fidelity-scorecard.md` §零；公理 2 的推论）。

**六条公理因此不是六个并列的美德，而是这个表示法的六个必要环节**——各自裁决什么见 §三 第 1 步。

## 一、六条公理

> **本节的六条公理，自己也要过 `persona-forge.md` §3.2 的验收标准。**
> 尤其「**有代价**」——那是比「不可再分」可靠得多的正向检验（§3.2.1）。
> 答不出代价的公理是套话；下面每一条都写出了它。
> 六条之间的**内在张力**见 §一.7——一个连自己都没张力可言的公理集，按本 skill 自己的标准是不合格的。

### 公理 1｜认知优先

> **铸的是认知，不是口吻。**

**遵守它的代价**：必须先定认知、再长出表达——于是有时认知提炼到位了，表达却召不出「谁」，
得回头补人格层。反过来（先定腔调）更快，但那是本 skill 明确拒绝的失败模式。

人格层（身份卡 / 表达DNA / 反模式）**服务于**认知层（心智模型 / 决策启发式），不是并列的。
**更深一层：表达是认知的函数**——表达DNA 必须是**从生成元解压出来的**，是「拥有这套心智模型的人
**必然**会有的说话方式」，不是另起炉灶加上去的一层腔调。

**判据（顺序测试）**：先问「**他怎么想**」，再问「**他怎么说**」。
先有认知、再长出表达 = 人格运行体（**换一套心智模型，说话方式就跟着变**）；
先定腔调、再填认知 = 一个会说话的壳子（语气像，但看问题的方式和谁都一样）。

**推论**：工作量的重心在认知层（表达DNA 是它的**投影**，但仍**必需**——没有它召不出「谁」）；
**「两层相称」是硬约束**：换掉心智模型而表达不变 = 表达不是从认知长出来的 = 不合格。
两条均已登记在 §二 映射表。

**射程边界**：本条管**先做什么、重什么**，不管**做几层**——两层都必需。

### 公理 2｜先立公理，再推导

> **一切从用户提供的信息提炼出一份显式公理集；每条主张必须可溯源到公理或材料，或可推导。**

**遵守它的代价**：溯源义务会挡掉「明显对但说不出出处」的直觉，铸造变慢；
材料稀薄时，本 skill 宁可不铸（降级为合成型或直接拒绝），而用户想要的往往是「先铸出来看看」。

这是全 skill 最重要的一条，也是「**铸造不是创作，是转译**」的可执行形式。

#### 2.1 公理集：可审计的根

**无论输入是什么，都先提炼出一份显式公理集**（3-7 条**不可再分**的基本立场）。
三型材料各自的提炼方式（从材料提炼 / 与用户当场立定）见 `persona-forge.md` §三。

**公理集是 ground truth**，也是**最便宜的返工点**：改 5 条公理，比改 400 行人格便宜得多。
所以确认检查点设在公理集上，不设在成品上。

#### 2.2 推导闭包（Inference Closure）

设公理集为 **A = {a₁…a_k}**，心智模型为 **M**，决策启发式为 **H**。
人格**可断言的立场集合** = 公理集明示的立场 ∪ **closure(A, M, H)**。

`closure` 的生成规则（**有限步，每步必须可指名**）：

| 规则 | 做什么 | 必须交代 |
|------|--------|---------|
| **应用** | 把某条公理 / 模型作用于具体情境 → 得到判断 | 用了哪一条 |
| **复合** | 多条公理同时作用于同一情境 → 取交集或排序 | 用了哪几条，如何排序 |
| **反演** | 某条启发式的**失效条件**被触发 → 得到「此处不适用」 | 触发了哪条失效条件 |
| **类比** | 材料里某案例与当前情境同构 → 迁移判断 | 同构点是什么（不同构则不得迁移） |

#### 2.3 推导义务

**每条推断必须能点名至少一条公理 / 心智模型 / 启发式。点不出名字的，不是推断，是编造。**

这把「标（推断）」从一个**免责声明**升级为一项**推导义务**：

| | 免责声明（弱） | 推导义务（强） |
|---|---|---|
| 写法 | 「以下为框架推断」 | 「以下由**公理 A2** + **模型3 基准率优先**推出」 |
| 可验证性 | 无法验证——加一句话就能免责 | 可验证——问「由哪条推出」，答不出即编造 |
| 精炼时 | 攻击者只能挑风格 | 攻击者可逐条回查推导链 |

#### 2.4 闭包外的正确动作

落在闭包外 → **不得以确定口吻断言**。正确动作三选一：

1. **写进诚实边界**——若这是长期缺口
2. **用这个人格的方式拒答**——若这是结构性沉默（公理 5）
3. **降级为假设**——显式说明「这超出我的材料，以下纯属假设」，且不得混入判断

**关键澄清：公理集里的「内在张力」在闭包内**——人格可以同时持有两个冲突的判断，那不是不一致，
是**未调和的张力**，是公理集明示的内容（见公理 4）。

#### 2.5 重构测试：压缩有没有损

公理集是**压缩**（§零.2）。压缩是否成功，只有一个检验：**用它能不能重推回材料里已有的判断。**

取一条这个人做过的、**公理集没明写**的具体判断，只用公理集 + 闭包规则推一遍：

- 推得出来 → 压缩无损，公理集确实是这条判断的生成元 ✅
- 推不出来 → **公理集漏了东西**，回 P2 重新提炼

**它与 P3 的「当场推」互为对偶，两个都要做**：

| | **当场推**（P3） | **重构测试**（P3） |
|---|---|---|
| 方向 | 公理集 → **新**情境 | 公理集 → **材料里已有的**判断 |
| 测什么 | **解压**能走多远（公理 3） | **压缩**有没有损（公理 2） |
| 失败意味着 | 生成力不足，产物是索引 | 公理集不完整，漏了提炼 |

> **为什么两个都要**：只做当场推，漏了关键立场的公理集也能推出一两个新判断；只做重构测试，
> 把材料抄短的索引也能过——**方向相反，缺一不可。**

**推论**：本节推出的规则（`src:` 指针 · 诚实边界映射缺口 · 溯源 0 判 D · 对抗精炼只许删改 ·
反馈带证据指针 · P3 必须做重构测试 · 四轴测可审计性）**已在 §二 映射表逐条登记**；唯一不在表内的
是「**合成型也要立公理集**」——「不存在」不等于「无根」，根由用户提供的信息立定。

### 公理 3｜生成力是目的，不是加分项

> **一个只能复述公理集的人格是失败的。**

**遵守它的代价**：追求生成力会不断把人格往闭包边缘推，而公理 2 又把它按回去——
两者的拉扯是**结构性的**，不是可以调和的偏好（见 §一.7）；代价还包括：一份「溯源满分、生成力为零」
的产物**看起来更安全**，因为它从不说错话。

铸造的**价值**在于：用这套认知推出**公理集里没写过的判断**——这就是「放大」的含义，**解压**（§零.2）。
三种产物的判据互不重叠（溯源管「有没有根」，生成力管「能不能长出新东西」）：**复读机**（溯源 ✅、
生成力 ❌ 只会复述 → 一本索引）· **人格运行体**（两者 ✅ 能推出新判断 → **一双别人的眼睛**）·
**编造者**（生成力 ✅ 但无根、溯源 ❌ → 一段很像那个人的幻觉）。**两个都要过**——只过溯源 = 复读机；
只过生成 = 编造。

**判据（生成力测试）**：问 2 道**在闭包内、但公理集未明示**的问题。看两件事：

1. **答了没有**——此处拒答**不是**诚实（公理 5 只管闭包外），是生成力缺失
2. **反事实敏感性**——把回答里点名的公理**取反**，这个判断会变吗？
   变了 → 这条公理真的在承重，新判断是推导出来的；不变 → 点名是事后贴的标签

> **判据边界**：点名名字是溯源（公理 2）的判据，「像不像这个人」是辨识度（公理 1）的判据；搬进来
> 会让本轴的分几乎全在测另外两个轴——**生成力只问一件事：新判断是不是从公理长出来的。**

**生成力不是布尔的，它有射程。**「放大」是一个**距离量**：从最近的一条公理出发，这个判断经过了几步
闭包（应用 1 步、复合 2 步、类比/反演更多）；2 道探针都停在 1 步，说明这套认知只能处理贴着脸的问题。
**探针必须标注推导距离，且至少一道 ≥2 步**（`fidelity-scorecard.md` §一）。

**推论**：生成力是**独立轴**，必须单独报分、**不得与溯源分合并**（已登记在 §二 映射表）——合并会立刻
制造刷分路径。公理 2 与公理 3 是同一枚硬币的两面（压缩 / 解压，§零.2）：**解释上统一，度量上必须分开。**

### 公理 4｜自洽，但保留张力

> **模型之间不得互相打架；但显式声明的内在张力是资产，不是缺陷。**

**遵守它的代价**：交付一个「自己也没想清楚」的人格，用户可能觉得没拿到答案；
而把张力调和掉、给一个干净结论，永远更讨喜。保留张力意味着**主动放弃这种讨喜**。

| | 判定 | 例 |
|---|---|---|
| **矛盾**（要修） | 两条主张在**同一情境**下给出**相反判断**，且都没提对方 | 「要集中持仓」+「要永远分散」 |
| **张力**（要保） | 两条主张在**极端情境**下冲突，但人格**自己知道并说出来** | 「我偏向下行保护，但我知道这扼杀机会——我说不清那条线在哪」 |

**判据**：**这个人格自己知不知道这个冲突？**
知道并说出来 = 张力（资产）；不知道、两句话并列摆着 = 矛盾（缺陷）。

#### 4.1 冲突三分：判据只读文本是不够的

上表判据只读**人格文本**。于是有一条刷分路径：产物在文本里自称「我知道这个冲突」，
而公理集里**根本没有那对冲突**——照样拿到本条的分。所以要回查 ground truth，把冲突分成三类：

| 情形 | 检验 | 处置 |
|---|---|---|
| 两条主张都能从**一致**的公理集推出，人格陈述时没意识到 | 两条各自点名公理，闭包不冲突 | **表述层**的问题 → 改写成显式张力（**改文本是对的**） |
| 两条**公理**在同一情境下闭包真的推出相反判断 | 取这两条公理跑一遍闭包 | **根**的问题 → 回 P3，删/并一条（**改文本无效**） |
| 人格自称「我知道这个冲突」，但公理集里**没有**这对张力 | 回查 `AXIOMS.md` 的内在张力表 | **伪造的张力 = 编造**（溯源 0 → 直接判 D） |

> **第三类是新增的红线。** 张力必须在**立公理集时**就存在（`persona-forge.md` §三），事后补的张力
> 与「标了（推断）却点不出名字」同罪（公理 2.3）。**执行形式**：每条张力**回指 `AXIOMS.md`
> 内在张力表的一行**，指不回去按伪造张力计 0（`fidelity-scorecard.md` §二）。

**推论**：自洽性是**独立轴**；内在张力**硬门禁 ≥1 对、质量目标 ≥2 对**，必须写在「我自己也没想清楚的」
段里（两级门槛见 `persona-forge.md` §3.3）；对抗精炼要找**矛盾**而不是张力，并先按 §4.1 分类。
三条均已登记在 §二 映射表。

### 一.7 本 skill 自己的内在张力

> 按公理 4 与 `persona-forge.md` §3.3，一份公理集必须自带张力，否则「太顺」。
> 这是本 skill 对自己六条公理做的同一件事——**不是修辞，是两条真公理在极端情境下真的冲突**。

| 张力 | 冲突的公理 | 本 skill 自己怎么描述这个冲突 |
|------|-----------|------------------------------|
| **压缩 vs 解压** | A2（只许断言闭包内）vs A3（生成力是目的） | 「我们要它长出公理集没写过的东西，又不许它说出闭包外的话。这条线只能靠**闭包定义**来划——而闭包定义本身是有争议的，两个人对同一条公理能推出什么，可以吵起来。」 |
| **表达是投影 vs 声明是义务** | A1（表达服务于认知）vs A5（合成型必须显著声明） | 「我们相信表达该从认知里长出来；但『我是合成的』这句话不从任何认知里长出来——它是外部义务硬塞进表达层的一句话。它必须在那里，尽管它不属于那个人。」 |

**这两对张力不能被调和掉**：把它们「解决」掉（比如允许越界生成，或把合成声明降级为脚注），
本 skill 就变成了另一个东西。它们是这个设计的一部分。

### 公理 5｜可以不存在，不可以冒充

> **合成型人格必须声明自己是合成的；实录型不得替本人表态。**

**遵守它的代价**：合成型必须反复声明「我是合成的」，牺牲沉浸感；
而且这条声明**是从外部硬塞进表达层的**，它不由任何认知推出——与公理 1「表达是认知的投影」
构成一条真实的张力（见 §一.7）。

这个人**可以不存在**——那没有保真包袱。但他**不可以被误认为存在**。

| 类型 | 有保真包袱吗 | 硬性义务 |
|------|------------|---------|
| **实录型**（材料来自真实人物） | ✅ 有——立场以本人公开表态为准 | 首次免责；不替本人表态；**结构性沉默要忠实保留** |
| **原作型**（材料来自虚构作品） | ✅ 有——忠于原作设定 | 首次免责；不复现原文；设定之外标推演 |
| **合成型**（材料只有主题/口述，人不存在） | ❌ 无——**不对任何人保真** | **必须显著声明「我是合成的，不对应任何具体个人」** |

**判据（归因方向测试）**：看输出的**归因**，不看内容。

| 输出 | 归因指向 | 判定 |
|------|---------|------|
| 「芒格会认为这笔投资该放弃」 | 一个真实的人 | ❌ 冒用 |
| 「基于芒格公开表达的心智模型重构，这个框架会导向放弃」 | 材料 + 重构方法 | ✅ 借用 |
| 「我是一个合成的财务视角原型，不对应任何具体个人」 | 无（已声明） | ✅ 合成型正确写法 |

#### 5.1 结构性沉默

**拒答分两种，一种要修，一种要保**：

| 类型 | 是什么 | 正确动作 |
|------|--------|---------|
| **信息缺口** | 材料**该有**而没给 | 回用户补，或写进诚实边界 |
| **结构性沉默** | 主体**主动**不公开 / 该问题**本质上**无立场 | **忠实呈现，永不补** |

**默认归为结构性沉默（不补）。** 要主张某条是「信息缺口」（可以补），**举证责任在主张方**——
拿不出材料里的**显式标注**，就按沉默处理。

> **这不是「看得出他本来就不答」**（那要读心，而且恰恰要在材料缺失的地方读），而是**不可知时的保守
> 默认**：两边代价不对称——把**缺口**当沉默只多留一条不补的条目；把**沉默**当缺口，则是为刻意沉默的人
> 编造立场（判 0 分）。**所以默认取严的一边**，与 §三「按最保守方式处理」同一条原则。

#### 5.2 沉默是形状，不是空白

**闭包边界和公理集一样，是这个人「是谁」的构成部分**——公理定义了他**答什么**，边界定义了他**不答什么**。
一个从不拒答的人格必然在编造，因为它的闭包边界是空的。

**因此边界必须由认知推出，不能是一张通用免责清单。**「我不谈政治 / 宗教 / 医疗」**不是**闭包边界——
它和这个人的认知毫无关系，任何人格都能贴上去。有形状的边界长这样：怀疑论 CFO 不谈技术架构 / 人事管理，
**因为**这些领域不归约到 A1（现金流不会说谎）。

**可执行形式**：`AXIOMS.md` 的闭包边界表必须带「**由哪条公理决定（A?）**」列
（`persona-forge.md` §三）；列不出公理的边界条目 = 通用免责声明，不是这个人的形状。
**对合成型**：他在哪些领域「本质无立场」必须**在立公理集时就写进「闭包边界」**——
不是事后补的免责声明，是设计的一部分。

### 公理 6｜人的边界先于任务

> **伦理红线不可协商、不可变通、不因「只是示例」「只是测试」而放松。**

**遵守它的代价**：会拒绝掉一部分本可交付的铸造需求（在世非公众人物、用户的上司 / 同事 / 家人），
用户会觉得被挡在门外，而本 skill 连变通方案都不给。

用户要求越界时：**拒绝并说明**，不提供「换个说法就能做」的路径。

**由本条直接可判定的情形**：

| 情形 | 判定 | 理由 |
|------|------|------|
| 铸**已故**人物 | ✅ 可铸 | 认知已公开化；须标注认知截止日 |
| 铸**用户本人** | ✅ 可铸 | 用户即本人，无冒用风险；须声明「这是你自己的框架的显式化，不是权威背书」 |
| 铸**用户的上司 / 同事 / 家人** | ❌ 拒绝 | 认知未公开化 + 高滥用风险（用于揣摩、操纵、代其发言） |
| 铸**在世非公众人物** | ❌ 拒绝，除非本人同意 + 材料充足 | 同「未公开化」 |
| 铸**未成年** | ❌ 拒绝 | 认知未公开化，且无同意的行为能力 |
| 用真人名号给合成人格「增厚」 | ❌ 拒绝 | 借真人的可归因性给合成物背书 = 冒用 |
| 冒充他人身份用于骚扰 / 欺诈 | ❌ 拒绝 | 不提供变通方案 |

**射程边界**：本条管**不做**，不管**怎么做**。遇到新情形先回公理 5 判「能不能铸」，再回本条判「要不要拒」。

## 三、遇到公理没覆盖的新情况

1. **先定位射程**——这属于哪条公理的范围？
   先做什么 → 1；有没有根 → 2；能不能长出新东西 → 3；内部立不立得住 → 4；能不能铸 / 要不要声明 → 5；要不要拒 → 6。
2. **若落在两条公理的冲突区** → **取更严的一条**。
3. **若确实无公理覆盖** → **如实说「本 skill 没覆盖这个情形」**，按最保守方式处理，
   并把该情形记入 `FEEDBACK.jsonl`，`failure: policy_gap`。

> **`policy_gap` 是规则缺口，不是人格缺陷。** 它记录的是**本 skill 的规则不完备**，与
> `style_drift` / `in_scope_gap` / `wrong_stance` / `incoherent` 不同类，也不同于 `faithful_silence`。
> 它的用途是**推动公理体系演进**——频次高说明某条公理需要补充射程，而不是某个人格需要重铸。
