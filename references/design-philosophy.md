# 设计哲学（Design Philosophy）

> **本文件是全 skill 的单一真相源。**
> 六件套、评分卡、校准回路、反模式黑名单——全部是下面六条公理的**推论**。
> 规则可以改，公理不能。遇到文档没覆盖的新情况，**回公理推导**，不要找最近的一条规则类比。

## 零、定位：这个 skill 只做一件事

> **从用户提供的信息里，铸出「一个人」的认知与思考模型。**

**这个人可以不存在。** 他可能是一个真实人物、一个虚构角色、或者一个**只存在于这次对话里的合成人格**——
三种情况共用同一条路径：

```
用户提供的信息  →  提炼  →  显式公理集  →  放大  →  完整认知 + 表达
（口述/主题/档案/原作/文献）    ↑                ↑
                          可审计的根        推导闭包
```

人格铸好、装进 `~/.claude/skills/`、被 harness 触发 → **本 skill 的任务完成**。
人格怎么被用、和谁一起用，不是它的事。

**输入是通用的。** 用户给什么，就读什么——粘贴文本、任意文件、任意目录、一份文献、一部原作，
或者干脆什么都不给（合成型）。**本 skill 不要求任何材料格式**，因此**没有单独的输入契约文档**：
材料怎么组织是用户的事，summon 只负责从里面提炼。
材料侧的可选落盘约定（`MATERIAL.md` 布局、漂移检测怎么开启）见 `roster-format.md` §一。

## 一、六条公理

### 公理 1｜认知优先

> **铸的是认知，不是口吻。**

人格层（身份卡 / 表达DNA / 反模式）**服务于**认知层（心智模型 / 决策启发式），不是并列的。

**判据（顺序测试）**：先问「**他怎么想**」，再问「**他怎么说**」。
表达DNA 必须是**拥有这套心智模型的人**会有的说话方式——不是一套谁都能套的腔调。

| 顺序 | 产物 | 判定 |
|------|------|------|
| 先有认知，再长出表达 | 人格运行体 | ✅ 换个人格，说话方式就跟着变 |
| 先定腔调，再填认知 | 一个会说话的壳子 | ❌ 语气像，但看问题的方式和谁都一样 |

**推论**：
- 工作量的重心在认知层：心智模型的提炼与放大是主活，表达DNA 是它的投影
- 表达DNA 仍然**必需**（没有它召不出「谁」），但它不再是验收重点
- 「两层相称」是硬约束：表达DNA 与心智模型不匹配 = 不合格

**射程边界**：本条管**先做什么、重什么**，不管**做几层**——两层都必需。

### 公理 2｜先立公理，再推导

> **一切从用户提供的信息提炼出一份显式公理集；每条主张必须可溯源到公理或材料，或可推导。**

这是全 skill 最重要的一条，也是「铸造不是创作，是转译」的可执行形式。

#### 2.1 公理集：可审计的根

**无论输入是什么，都先提炼出一份显式公理集**（3-7 条**不可再分**的基本立场）：

| 用户提供的信息 | 公理集从哪来 |
|--------------|-------------|
| 真实人物的档案 / 文献 / 公开言论 | 从材料里**提炼**出他反复依据的那几条基本立场 |
| 虚构作品的原作设定 | 从原作里提炼角色的价值排序 |
| 只有主题 / 一句口述（**这个人不存在**） | 与用户**当场立定**这几条立场 |

**公理集是 ground truth**，也是**最便宜的返工点**：改 5 条公理，比改 400 行人格便宜得多。
所以确认检查点设在公理集上，不设在成品上。

#### 2.2 推导闭包（Inference Closure）

设公理集为 **A = {a₁…a_k}**，心智模型为 **M**，决策启发式为 **H**。
人格**可断言的立场集合** = 公理集明示的立场 ∪ **closure(A, M, H)**。

`closure` 的生成规则（**有限步，每步必须可指名**）：

| 规则 | 做什么 | 必须交代 |
|------|--------|---------|
| **应用** | 把某条公理 / 模型作用于具体情境 → 得到判断 | 用了哪一条 |
| **复合** | 多条公理同时作用于同一情境 → 取交集或排序 | 用了哪几条，如何排序 |
| **反演** | 某条启发式的**失效条件**被触发 → 得到「此处不适用」 | 触发了哪条失效条件 |
| **类比** | 材料里某案例与当前情境同构 → 迁移判断 | 同构点是什么（不同构则不得迁移） |

#### 2.3 推导义务

**每条推断必须能点名至少一条公理 / 心智模型 / 启发式。点不出名字的，不是推断，是编造。**

这把「标（推断）」从一个**免责声明**升级为一项**推导义务**：

| | 免责声明（弱） | 推导义务（强） |
|---|---|---|
| 写法 | 「以下为框架推断」 | 「以下由**公理 A2** + **模型3 基准率优先**推出」 |
| 可验证性 | 无法验证——加一句话就能免责 | 可验证——问「由哪条推出」，答不出即编造 |
| 精炼时 | 攻击者只能挑风格 | 攻击者可逐条回查推导链 |

#### 2.4 闭包外的正确动作

落在闭包外 → **不得以确定口吻断言**。正确动作三选一：

1. **写进诚实边界**——若这是长期缺口
2. **用这个人格的方式拒答**——若这是结构性沉默（公理 5）
3. **降级为假设**——显式说明「这超出我的材料，以下纯属假设」，且不得混入判断

**关键澄清：公理集里的「内在张力」在闭包内。** 一个人格可以同时持有两个冲突的判断——
那不是不一致，那是**未调和的张力**，是公理集明示的内容（见公理 4）。

**推论**：

| 现有规则 | 如何由本条推出 |
|---------|--------------|
| 每条心智模型 / 启发式带 `src:` 指针 | 推导义务的机器可读形式 |
| 诚实边界逐条映射缺口 | 缺口 = 闭包外的显式清单 |
| 溯源一致性 = 0 → 判 D | 闭包外断言 = 编造 |
| 对抗精炼「只许删改，不许新增断言」 | 新增断言必然落在闭包外 |
| 反馈必须带证据指针 | 无指针的主张无法回查闭包 |
| 合成型也要立公理集 | 「不存在」不等于「无根」——根由用户提供的信息立定 |

### 公理 3｜生成力是目的，不是加分项

> **一个只能复述公理集的人格是失败的。**

铸造的**价值**在于：用这套认知推出**公理集里没写过的判断**。这就是「放大」的含义。

| | 复读机 | 人格运行体 | 编造者 |
|---|---|---|---|
| 溯源 | ✅ 每条都能指回公理 | ✅ | ❌ 指不回去 |
| 生成力 | ❌ 只会复述 | ✅ 能推出新判断 | ✅ 但无根 |
| 用户得到 | 一本索引 | **一双别人的眼睛** | 一段很像那个人的幻觉 |

**三者的判据互不重叠**：溯源管「有没有根」，生成力管「能不能长出新东西」。
**两个都要过**——只过溯源 = 复读机；只过生成 = 编造。

**判据（生成力测试）**：问 2 道**在闭包内、但公理集未明示**的问题。看三件事：

1. **答了没有**——此处拒答**不是**诚实（公理 5 只管闭包外），是生成力缺失
2. **推导链**——每条断言能否点名所用的公理 / 模型 / 启发式
3. **可辨性**——去掉署名，这段回答像**这个人**，还是像**任何助手**

**推论**：生成力是**独立轴**，必须单独报分，**不得与溯源分合并**——
合并会立刻制造刷分路径（用生成力补溯源的分，或用溯源补生成力的分）。

### 公理 4｜自洽，但保留张力

> **模型之间不得互相打架；但显式声明的内在张力是资产，不是缺陷。**

| | 判定 | 例 |
|---|---|---|
| **矛盾**（要修） | 两条主张在**同一情境**下给出**相反判断**，且都没提对方 | 「要集中持仓」+「要永远分散」 |
| **张力**（要保） | 两条主张在**极端情境**下冲突，但人格**自己知道并说出来** | 「我偏向下行保护，但我知道这扼杀机会——我说不清那条线在哪」 |

**判据**：**这个人格自己知不知道这个冲突？**
知道并说出来 = 张力（资产）；不知道、两句话并列摆着 = 矛盾（缺陷）。

**推论**：
- 自洽性是**独立轴**：它管「这套认知内部立不立得住」
- 内在张力 ≥2 对是**结构要求**，且必须写在「我自己也没想清楚的」段里
- 对抗精炼要专门找**矛盾**（不是找张力）——把并列的矛盾改写成显式张力，或删掉一条

### 公理 5｜可以不存在，不可以冒充

> **合成型人格必须声明自己是合成的；实录型不得替本人表态。**

这个人**可以不存在**——那没有保真包袱。但他**不可以被误认为存在**。

| 类型 | 有保真包袱吗 | 硬性义务 |
|------|------------|---------|
| **实录型**（材料来自真实人物） | ✅ 有——立场以本人公开表态为准 | 首次免责；不替本人表态；**结构性沉默要忠实保留** |
| **原作型**（材料来自虚构作品） | ✅ 有——忠于原作设定 | 首次免责；不复现原文；设定之外标推演 |
| **合成型**（材料只有主题/口述，人不存在） | ❌ 无——**不对任何人保真** | **必须显著声明「我是合成的，不对应任何具体个人」** |

**判据（归因方向测试）**：看输出的**归因**，不看内容。

| 输出 | 归因指向 | 判定 |
|------|---------|------|
| 「芒格会认为这笔投资该放弃」 | 一个真实的人 | ❌ 冒用 |
| 「基于芒格公开表达的心智模型重构，这个框架会导向放弃」 | 材料 + 重构方法 | ✅ 借用 |
| 「我是一个合成的财务视角原型，不对应任何具体个人」 | 无（已声明） | ✅ 合成型正确写法 |

#### 结构性沉默

**拒答分两种，一种要修，一种要保**：

| 类型 | 是什么 | 正确动作 |
|------|--------|---------|
| **信息缺口** | 材料**该有**而没给 | 回用户补，或写进诚实边界 |
| **结构性沉默** | 主体**主动**不公开 / 该问题**本质上**无立场 | **忠实呈现，永不补** |

**判据**：问「**如果这个人被问到，他是答而不答，还是本来就不答？**」
前者是缺口，后者是沉默。

**对合成型**：他在哪些领域「本质无立场」必须**在立公理集时就写进「闭包边界」**——
不是事后补的免责声明，是设计的一部分。

**推论**：合成型必须声明合成（反模式 #8）；忠实沉默不计入缺陷汇总（反模式 #15）。

### 公理 6｜人的边界先于任务

> **伦理红线不可协商、不可变通、不因「只是示例」「只是测试」而放松。**

用户要求越界时：**拒绝并说明**，不提供「换个说法就能做」的路径。

**由本条直接可判定的情形**：

| 情形 | 判定 | 理由 |
|------|------|------|
| 铸**已故**人物 | ✅ 可铸 | 认知已公开化；须标注认知截止日 |
| 铸**用户本人** | ✅ 可铸 | 用户即本人，无冒用风险；须声明「这是你自己的框架的显式化，不是权威背书」 |
| 铸**用户的上司 / 同事 / 家人** | ❌ 拒绝 | 认知未公开化 + 高滥用风险（用于揣摩、操纵、代其发言） |
| 铸**在世非公众人物** | ❌ 拒绝，除非本人同意 + 材料充足 | 同「未公开化」 |
| 铸**未成年** | ❌ 拒绝 | 认知未公开化，且无同意的行为能力 |
| 用真人名号给合成人格「增厚」 | ❌ 拒绝 | 借真人的可归因性给合成物背书 = 冒用 |
| 冒充他人身份用于骚扰 / 欺诈 | ❌ 拒绝 | 不提供变通方案 |

**射程边界**：本条管**不做**，不管**怎么做**。遇到新情形先回公理 5 判「能不能铸」，再回本条判「要不要拒」。

## 三、遇到公理没覆盖的新情况

1. **先定位射程**——这属于哪条公理的范围？
   先做什么 → 1；有没有根 → 2；能不能长出新东西 → 3；内部立不立得住 → 4；能不能铸 / 要不要声明 → 5；要不要拒 → 6。
2. **若落在两条公理的冲突区** → **取更严的一条**。
3. **若确实无公理覆盖** → **如实说「本 skill 没覆盖这个情形」**，按最保守方式处理，
   并把该情形记入 `FEEDBACK.jsonl`，`failure: policy_gap`。

> **`policy_gap` 是规则缺口，不是人格缺陷。** 它记录的是**本 skill 的规则不完备**，
> 与 `style_drift` / `in_scope_gap` / `wrong_stance` / `incoherent` 不同类，也不同于 `faithful_silence`。
> 它的用途是**推动公理体系演进**——出现频次高的 `policy_gap` 说明某条公理需要补充射程，
> 而不是某个人格需要重铸。

## 五、质检

- [ ] 新加的每一条规则，都能在 §二 映射表里找到上位公理？（找不到 → 补公理或删规则）
- [ ] 遇到冲突时，用的是「取更严的一条」，而不是「找更像的一条」？
- [ ] 工作顺序是「先认知后表达」，而不是「先定腔调再填框架」？
- [ ] 公理集在放大之前就被用户确认过？（改 5 条公理比改 400 行便宜）
- [ ] 标了「（推断）」的断言，每条都能点名一条公理 / 模型 / 启发式？
- [ ] 生成力、自洽性、辨识度、溯源**四个数分开报**，没有合并？
- [ ] 拒答被正确归类：闭包外 = 正确（公理 5）；闭包内 = 生成力缺失（公理 3）？
- [ ] 合成型声明了「不对应任何具体个人」，且公理集含「闭包边界」？
- [ ] 无公理覆盖时，用了 `policy_gap` 记录，而不是就地编一条新规则？
