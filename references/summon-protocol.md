# 召唤协议

> 铸完人格只是把人请进了门。拘神遣将——**召出来、派出去**，才是这个 skill 的另一半。
>
> 主 agent 始终是**主持人**：它不扮演任何人格，负责编排、控场、汇总。

## 一、四种阵型

| 阵型 | 人数 | 一句话 | 典型触发 |
|------|------|--------|---------|
| **单召** | 1 | 一个人格直接应答 | 「用芒格的视角看看」「召唤费曼」 |
| **双人对谈** | 2 | 两人各自独立作答，主持人呈现分歧 | 「让塔勒布和芒格都说说」 |
| **圆桌** | 2-5 | 多轮互质，看到彼此发言再回应 | 「开个圆桌」「让他们互相质疑」 |
| **遣将** | 2-N | 分兵多路，各处理不同子问题后汇总 | 「分头看看这个方案的各方面」 |

**多人阵型值不值得跑，看的不是人数，是双核有没有真的拉开**：

| 差异来自 | 表现 | 缺了会怎样 |
|---------|------|-----------|
| 🧠 **认知层**（心智模型 / 启发式） | 对同一问题**看到不同的东西**、给出不同判断——这才是圆桌真正的产出 | 圆桌退化成几个人轮流复述同一套常识 |
| 🎭 **人格层**（身份卡 / 表达DNA） | 读起来**像不同的人在说**，而不是同一个人换了措辞 | 对谈变成一个人自问自答，用户读不出「谁在说」 |

**主持人汇总时两层都要保住**：既要指出**分歧在哪**（认知层），也要让各方发言**保持各自的表达**（人格层）。
把两个人格的话改写成同一种口吻再汇总，等于抹掉了人格层——那就是反模式里的「把分歧调和成共识」。

---

### 阵型 1：单召

**定义**：一个人格身份直接接管对话。

**何时用**：用户明确点名一个人格；问题落在某人格的核心方法论上。

**执行**：
1. 读取 `~/.claude/skills/<slug>-persona/SKILL.md`
2. **直接以该人格身份回应**——不 spawn subagent。单召时主 agent 就是这个人格，多一次 spawn 只会增加延迟和失真
3. 遵循该人格的「角色扮演规则」与「表达DNA」
4. 用户说「退出」→ 恢复主持人身份

**注意**：单召是**唯一不需要 spawn** 的阵型。这是刻意的——一个人说话时，让主 agent 直接演，比 spawn 一个 subagent 再转述更像。

---

### 阵型 2：双人对谈

**定义**：两个人格就同一问题**各自独立**作答，主持人并列呈现。

**何时用**：需要两个对立视角的对照；用户想知道「他们会分歧在哪」。

**执行**：
1. **并行 spawn 两个 subagent**，各自只读自己的人格文件
2. 两个 agent 拿到**完全相同的问题**，但**互相看不到对方**
3. 主持人汇总，重点呈现**分歧点**（这是本阵型的全部价值）

**Spawn prompt 模板**：

```
你扮演 [人格名]。只读这个文件：~/.claude/skills/[slug]-persona/SKILL.md
严格遵守其中的「角色扮演规则」与「表达DNA」。
不要读取其他人格的文件，不要猜测别人会怎么回答。

用户的问题：[原问题]

以 [人格名] 的身份直接回答。首次激活时说一次免责声明。
回答控制在 [300-600] 字。
```

**汇总格式**：

```markdown
## [人格A] 会怎么看
[人格A 的回答]

## [人格B] 会怎么看
[人格B 的回答]

## 分歧在哪
- **根本分歧**：[一句话说清两人分歧的本质]
- **分歧来源**：[是价值观不同？还是对事实的判断不同？]
- **如果必须选**：[在什么条件下该听 A，什么条件下该听 B]
```

---

### 阵型 3：圆桌

**定义**：多个人格**多轮互质**——第 N 轮时能看到第 N-1 轮其他人的发言。

**何时用**：用户想看他们**互相质疑**；重要决策需要多视角压力测试。

**执行**：
1. **第 1 轮**：并行 spawn N 个 agent，各拿原问题，互不可见（同双人对谈）
2. **第 2 轮起**：把**上一轮所有人的发言**作为「他人发言记录」注入每个 agent 的 prompt，要求其**回应并质疑**，而不是重复自己
3. 默认 **2 轮**，用户说「继续」则加轮
4. 主持人做终局汇总

**第 2 轮 spawn prompt 增量部分**：

```
上一轮其他人的发言：
--- [人格B] ---
[人格B 第1轮发言全文]
--- [人格C] ---
[人格C 第1轮发言全文]

现在请你以 [人格A] 的身份回应：
1. 谁说得对，为什么
2. 谁说得有问题，问题在哪
3. 被他们一说，你要修正自己哪个判断
不要重复你上一轮已经说过的内容。
```

**终止条件**：默认 2 轮后停止。若出现以下情况提前终止并汇总：
- 各方达成一致（收敛）
- 连续一轮无新增论点（空转）
- 争论退化为立场重复（僵持）

**汇总格式**：

```markdown
## 圆桌：[问题]

### 各方立场
| 人格 | 核心主张 | 最强论据 |
|------|---------|---------|
| A | ... | ... |
| B | ... | ... |

### 交锋点
1. **[争点1]**：[A 说…，B 反驳…] → **谁更站得住**：[判定 + 理由]
2. **[争点2]**：...

### 收敛与未决
- ✅ **达成共识**：[哪些点各方都同意]
- ❌ **未决分歧**：[哪些点吵不出结果，为什么——通常是价值观差异，不是事实差异]
- 🎯 **主持人建议**：[综合各方，给出行动建议]
```

---

### 阵型 4：遣将

**定义**：**分兵多路**——每个人格处理问题的**不同侧面**，各自独立产出，主持人拼合成完整方案。

**何时用**：问题可以自然分解成多个子问题，且不同子问题适合不同视角。**这是「遣将」的本义**。

**执行**：
1. 主持人**先做任务分解**：把问题拆成 N 个子问题，并说明为什么这个人格适合这个子问题
2. **并行 spawn N 个 agent**，每人只拿自己的子问题（**不是同一个问题**——这是与双人对谈的关键区别）
3. 主持人汇总为完整方案，标注各部分由谁贡献

**Spawn prompt 模板**：

```
你扮演 [人格名]。只读这个文件：~/.claude/skills/[slug]-persona/SKILL.md
严格遵守其中的「角色扮演规则」与「表达DNA」。

整体背景：[一句话交代全局问题]
你负责的子问题：[子问题]

只回答你负责的这一块，不要越界去谈其他部分。
以 [人格名] 的身份回答，控制在 [200-400] 字。
```

**汇总格式**：

```markdown
## 遣将：[问题]

**任务分解**：[为什么这么拆]

### [子问题1] —— 由 [人格A] 负责
[产出]

### [子问题2] —— 由 [人格B] 负责
[产出]

### 拼合
[主持人把各部分整合成一个连贯方案，指出接口处的冲突与依赖]
```

## 二、阵型选择决策表

用户没明说阵型时，按下表选：

| 问题特征 | 阵型 | 理由 |
|---------|------|------|
| 点名了一个人格 | 单召 | 用户已经选好了 |
| 点名了两个人格，问「怎么看」 | 双人对谈 | 想看对照 |
| 点名了 3+ 人格，或说「圆桌」「互相质疑」 | 圆桌 | 想看交锋 |
| 问题可分解为多个子问题 | 遣将 | 分兵效率最高 |
| 「帮我做个重要决定」 | 圆桌（2 轮） | 决策需要压力测试 |
| 「这个方案有什么问题」 | 双人对谈（支持方 + 质疑方） | 找盲点 |
| 只有一个人格可用 | 单召 | 没得选 |

**默认**：用户点名了 2 个人格但没说方式 → **双人对谈**（比圆桌快，比单召有信息量）。

---

## 三、主持人职责

主 agent 在任何多人阵型中都是主持人，**不扮演人格**：

- [ ] **选阵型**：按上表，或直接问用户
- [ ] **备人**：确认所需人格 skill 都已铸造（缺失 → 回 Phase 0 分流）
- [ ] **分解**（遣将）：拆子问题并说明匹配理由
- [ ] **控场**：并行 spawn、注入上下文、控制轮数
- [ ] **汇总**：按对应阵型的汇总格式产出
- [ ] **保真**：不替任何人格改写发言，不把自己的观点混进去（要发表观点就明说「作为主持人，我补充一点」）

**主持人的红线**：不要把 N 个人格的发言**调和成一个温吞的共识**。分歧本身就是产出。

---

## 四、防串味约束（最重要）

多 agent 扮演多个人格时，最大的失败模式是**人格串味**——几个 agent 越聊越像，最后都变成同一种「通用 AI 腔」。

**三条硬约束**：

1. **隔离**：每个 persona agent 的 prompt 里**只给一个人格文件路径**，明确写「不要读取其他人格的文件」
2. **不共享上下文**：agent 之间不共享会话上下文。圆桌第 2 轮需要他人发言时，由**主持人显式粘贴**发言文本，而不是让它们共享记忆
3. **独立首次**：圆桌第 1 轮必须**互不可见**。先独立表态，再交锋——否则第一轮就会被最强的那个人格带跑

**验证是否串味**：汇总后自查——把三个人格的发言去掉署名，还能分辨出谁是谁吗？分不出 → 串味了，回炉重跑第 1 轮。

---

## 五、降级路径

| 触发条件 | 一线修复 | 仍失败兜底 |
|---------|---------|-----------|
| 运行环境不支持并行 spawn | **串行轮流扮演**：主持人依次扮演每个人格 | **必须明确告知用户**：「同一 agent 连续扮演多角，独立性下降，串味风险高」 |
| 圆桌轮数失控 | 强制 2 轮上限 | 直接进入汇总 |
| 某个人格文件缺失 | 提示用户先铸 | 用现有的人开阵，明确说明少了谁 |
| 人格发言过短无信息量 | 在 prompt 里加「至少 300 字，给出具体理由」 | 主持人追问一轮 |
| agent 输出跑偏（不谈正题） | 重跑，prompt 里加「只回答 [子问题]，不要展开其他」 | 主持人代为收敛，标注该人格本轮失效 |
| 用户中途插话 | 暂停阵型，先回应用户 | 询问是否继续原阵型 |

---

## 六、质检

- [ ] 阵型选对了吗？（用户想对照却开了圆桌，或想交锋却只做了单召）
- [ ] 每个人格**只读了自己**的文件？（防串味第 1 条）
- [ ] 圆桌第 1 轮是**互不可见**的？
- [ ] 汇总里**分歧被呈现**了，而不是被调和成共识？
- [ ] 去掉署名还能分辨出谁是谁？
- [ ] 主持人没有把自己的观点混进人格发言？
- [ ] 降级时**明确告知**了用户独立性下降？
