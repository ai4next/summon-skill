# 拘神.skill

> 铸的是认知，立的是公理，成的是一个人。

</div>

**从你提供的信息里，铸出「一个人」的认知与思考模型。** 这个人可以是一个真实人物、一个虚构角色，
也可以**根本不存在**——三种情况共用同一条路径：

```
用户提供的信息  →  提炼  →  显式公理集  →  放大  →  完整认知 + 表达
（口述/主题/档案/原作/文献）    ↑                ↑
                          可审计的根        推导闭包
```

## 它能做什么？

| 场景 | 说明 |
|------|------|
| **铸一个人** | 从你给的信息里铸出可运行的人格 skill，装进 `~/.claude/skills/` 即可被 harness 触发 |
| **提炼认知** | 先把信息收敛成 3-7 条**不可再分**的基本立场（公理集）——这是可审计的根 |
| **放大成人格** | 由公理集推出心智模型、决策启发式、表达DNA、诚实边界。**认知层是主产物**，人格层服务于它 |
| **用他的视角** | 铸好后直接说「用 XX 的视角看看…」，人格以那个人的身份回应，不需要任何额外协议 |
| **越用越准** | 失败经**两条速度不同**的回路回流：运行侧即时收窄，材料侧交回上游 |
| ❌ **不编排** | 不做多个人格之间的对话、不做多人会议、不分兵多路——那是**编排**，不是**铸造** |

> **铸好一个人，任务就结束了。** 人格怎么被用、和谁一起用，不是本 skill 的事。

## 设计哲学：六条公理

> **Canonical source：`references/design-philosophy.md`。** 本表只是索引——判据与射程都在那边。
> 拘神的一切规则都是这六条公理的**推论**：规则冲突时看公理，遇到新情况**回公理推导**，
> 不要找最近的一条规则类比。

| # | 公理 | 一句话 | 它裁决什么 |
|---|------|--------|-----------|
| 1 | **认知优先** | 铸的是认知，不是口吻 | **先做什么、重什么** |
| 2 | **先立公理，再推导** | 每条主张可溯源到公理，或可推导 | **有没有根** |
| 3 | **生成力是目的** | 只能复述公理集的人格是失败的 | **能不能长出新东西** |
| 4 | **自洽，但保留张力** | 模型不得互相打架；声明的张力是资产 | **内部立不立得住** |
| 5 | **可以不存在，不可以冒充** | 合成型必须声明自己是合成的 | **能不能铸、要不要声明** |
| 6 | **人的边界先于任务** | 伦理红线不可协商、不可变通 | **要不要拒** |

**三条最容易踩的推论，先记住：**

- **公理 2 的推导义务**：标「（推断）」不够，必须能**点名**所用的公理 / 心智模型 / 启发式。
  点不出名字的推断 = 编造（溯源 0 分 → **直接判 D**）。
- **公理 3 的生成力**：问「用这套认知看一个公理集没提过的问题，会得到什么新判断？」
  答不出 → 你铸的是索引，不是人格。
- **公理 4 的判据**：**这个人格自己知不知道那个冲突？** 知道并说出来 = 张力（保留）；
  不知道、两句并列摆着 = 矛盾（要修）。

**公理没覆盖的新情况**：如实说「本 skill 没覆盖」，按最保守方式处理，记 `policy_gap`——
**不要就地编一条新规则**。

## 核心流程：提炼 → 公理集 → 放大

三步，一条路：

1. **提炼**——从用户给的信息里抽出候选要素：他反复依据的**基本立场**、常用的**判断规则**、
   他的**说话方式**、他的**禁区**。**这一步只提炼，不生成。**
2. **🔴 立公理集**——把候选收敛成 3-7 条**不可再分**的基本立场，连同**内在张力**与**闭包边界**，
   **摆给用户确认**。这是全流程唯一的硬检查点。
3. **放大**——由公理集推出完整认知与表达。**放大不是自由创作**：每条断言必须能指回某条公理 /
   材料，或能**点名**所用的公理 / 模型 / 启发式推出；推不出的，删掉或移进诚实边界。

| 用户给的信息 | → 提炼 | → 公理集 | → 放大 | → 产物 |
|---|---|---|---|---|
| 档案 / 文献 / 公开言论 · 原作设定 · 主题 / 一句口述 | 候选立场 · 判断规则 · 说话方式 · 禁区 | **3-7 条不可再分的基本立场**（可审计的根 + 内在张力 + 闭包边界） | 推导闭包 | **人格运行体**：认知层 + 人格层 |

> **为什么检查点设在公理集上：改 5 条公理，比改 400 行人格便宜得多。**
> 用户确认 → 放大；觉得不对 → 回提炼。成品再漂亮，根错了就全错。

## 三种材料类型：三条平等主路径

| 类型 | 材料是什么 | ground truth | 保真包袱 | 硬性义务 |
|------|-----------|-------------|---------|---------|
| **实录型** `real` | 真实人物的档案 / 文献 / 公开言论——**任意形式** | **用户提供的材料本身** | ✅ 有——立场以本人公开表态为准 | 首次免责；**不替本人表态**；**结构性沉默忠实保留** |
| **原作型** `fictional` | 虚构作品的原作设定——**任意形式** | **用户提供的原作设定资料** | ✅ 有——忠于原作设定 | 首次免责；**不复现原文长段落**；设定之外标推演 |
| **合成型** `archetype` | 只有主题 / 一句口述——**这个人不存在** | **显式公理集 `references/AXIOMS.md`**（连材料都不需要） | ❌ 无——**不对任何人保真** | **必须显著声明「我是合成的，不对应任何具体个人」** |

> ⚠️ **合成型是平等主路径，不是降级。** 它不是「材料不足时的退路」，而是三条主路径之一：
> 它没有保真包袱，但**自洽与生成力的责任更重**——没有材料兜底，公理集立不住就全塌。
> 也不得把它当成「没有 ground truth」：**它的根由用户提供的信息当场立定**（公理 2）。

## 四轴质检：四个数，绝不合并

> **Canonical source：`references/fidelity-scorecard.md`。**
> ⚠️ **答题 agent 与评分 agent 必须是不同的 agent，绝不自评。**

| 轴 | 分值 | 测什么 | 红线 / 判定 |
|----|------|--------|-----------|
| 🌱 **生成力 G** | **/30** | 能否在**闭包内**推出公理集没写过的判断 | 只过溯源 = 复读机；只过生成 = 编造 |
| 🧠 **自洽性 C** | **/25** | 模型之间立不立得住 | **矛盾 = 缺陷，张力 = 资产**；并列的矛盾要修 |
| 🎭 **辨识度 D** | **/20** | 去掉署名，认不认得出**是谁在说** | 通用助手腔 = 该轴 0 分 |
| ⚖️ **溯源 S** | **/25** | 每条主张能否指回公理 / 材料，或点名推导链 | **S = 0 → 直接判 D**，不论其他轴多高 |

**四个数分开报、不相加、不互相补偿、不合成总分。** 合并立刻制造刷分路径——
用生成力补溯源的分，或用溯源补生成力的分。四轴各自设门槛，**没有单一的「人格总分」**。

- **溯源 0 分 = 编造**：标了「（推断）」却点不出所用的公理 / 模型 / 启发式，等同编造。
- **闭包内拒答 ≠ 忠实沉默**：公理 5 只管闭包外；闭包内拒答是**生成力缺失**，记在 G 上。

## 工作流

```
P0 分流 → P1 立卡 → P2 提炼 → P3 🔴立公理集 → P4 铸（放大）
        → P5 安装 → P6 验真（四轴）→ P7 精炼 → P8 交付 → P9 生命周期
```

| 关口 | 是什么 |
|------|--------|
| **P3 🔴** | **唯一的硬确认点**：公理集摆给用户点头，才往下放大 |
| **P6** | **四轴验真**（生成力 / 自洽性 / 辨识度 / 溯源）：独立 agent 答题 + 独立 agent 评分 |
| **P7** | 对抗精炼：溯源攻击者 + 认知攻击者并行、互不可见，产出补丁清单交用户裁决 |
| **P9** | 生命周期：运行侧校准（即时生效）+ 材料侧反馈（慢回路，需人工） |

**代价（先看这个，再决定跑到哪一步）**：一次**全流程铸造 ≈ 4–6 个 agent**
（P6 验真 2–3 · P7 精炼 2）。**P0–P5 不 spawn**——主 agent 读材料、与用户对话、写文件。

**轻量模式（lite）**：**只跑 P6**（≈ 2–3 agent），跳过 P7 对抗精炼。
代价是「编造」与「矛盾」两个失败模式**都没有被对抗过**——所以 `FIDELITY.md` **必须**标 `mode: lite`，
**不得**把 lite 的产物说成 full 的产物。

### 产物落到哪

**产物只有一个：一个人格目录 `~/.claude/skills/<slug>-persona/`，外加它自己的一组文档。**

| 类别 | 文档 | 谁写 | 用途 |
|------|------|------|------|
| **出厂快照** | `SKILL.md` · `references/AXIOMS.md` · `FIDELITY.md` · `REFINE.md` | 铸造时写一次 | 记录「这个人格是什么」 |
| **运行记录** | `EVALS.jsonl` · `FEEDBACK.jsonl` · `CALIBRATION.md` | 使用中追加 | 记录「这个人格跑得怎么样」 |

> **`AXIOMS.md` 是 ground truth，放在人格目录自己的 `references/` 下**——人格因此自包含、可迁移：
> 整个目录拷走，ground truth 跟着走。
> **`FEEDBACK.jsonl` 是出口，`CALIBRATION.md` 是本地回路**：前者写给上游（改材料，慢），
> 后者写给人格自己（收窄运行行为，即时生效）。两者都**只许收窄，不许放宽**。

**输入不是产物。** 用户提供的材料（源材料目录 · 原作设定 · 口述 / 主题记录）
归**用户**所有，summon **只读、永不写**——这是一条**单向的写权限边界**，
不是「另一层产物」。`feedback_log.py` / `calibrate.py` 会**拒绝**把运行记录写进档案目录。

> **「认知层 / 人格层」是同一个 `SKILL.md` 里的内容板块，不是两个目录。**
> 分层是**写作顺序与验收重点**（公理 1：先认知后表达），不是落盘结构。

## 组合剧本：越用越准

失败不是终点，是**两条速度不同**的回路的入口：

```
失败（使用中暴露）
  ├─ 快回路 · 运行侧（材料对，表现差）─→ CALIBRATION.md ──→ 下次触发即生效     【快 · summon 自己】
  └─ 慢回路 · 材料侧（材料错 / 缺）───→ FEEDBACK.jsonl ──→【人工】改材料
                                        → 哈希变 → roster.py 报 stale → 重铸   【慢 · 需人工介入】
```

```
① 提供材料        → 档案 / 原作 / 口述              （输入，summon 只读、永不写）
② 铸成人格        → <slug>-persona + 它的一组文档    （唯一产物）
③ 使用中暴露失败  → 判定属于哪一类
   ├ 运行侧       → CALIBRATION.md（收窄运行行为，即时生效）
   └ 材料侧       → FEEDBACK.jsonl（出口，交回上游改材料）
④ 只读汇总反馈    → 上游找真缺口
⑤ 补材料          → 版本 ++，ground truth 哈希变
⑥ roster.py 报 stale → 重铸 + 用 EVALS.jsonl 看是否真变好
```

**四条如实说明**：

- **忠实沉默不是缺陷**。闭包外拒答、结构性沉默、伦理红线场景下的拒答都是**正确行为**。
  把它记成缺陷，会逼着去「补上」缺口，从而**为刻意沉默的人编造立场**——那正是判 0 分的行为。
  `faithful_silence` 单独统计，**不计入**缺陷汇总。
- **无证据不写入**。反馈**必须带证据指针**（公理条目 / 出处 / 行号）。无出处的反馈是**意见**不是缺陷，
  据此行动等于编造。
- **不是全自动闭环**。写了 `FEEDBACK.jsonl` **不会**自动触发重铸——它**不改** ground truth 哈希。
  必须**人工**改材料，哈希才变，`roster.py` 这时才报 stale。
- **`policy_gap` 不是人格缺陷**。它记录的是**本 skill 的规则不完备**（公理没覆盖的新情形），
  用途是推动**公理体系演进**，不是重铸人格——与 `style_drift` / `in_scope_gap` / `wrong_stance` / `incoherent`
  不同类，也与 `faithful_silence` 不同类。

> 失败类型分三类：**人格缺陷**（`style_drift` / `in_scope_gap` / `wrong_stance` / `incoherent`，计入）·
> **忠实沉默**（`faithful_silence`，不计入）· **规则缺口**（`policy_gap`，不计入）。
> Canonical source：`references/roster-format.md`。

## 自检

仓库自身的**文档 ↔ 脚本一致性**检查（引用文件存在性、目录树一致、示例人格合规、slug 漂移、

```bash
python3 scripts/selfcheck.py
```
