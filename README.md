# 拘神.skill

> 铸的是认知，召的是视角，遣的是分工。铸完人格只是把人请进了门——召出来、派出去，才是它的一半。

</div>

## 它能做什么？

| 场景 | 说明 |
|------|------|
| 铸人格 | 把一份蒸馏档案锻成可运行的人格 skill，装进 `~/.claude/skills/` 即可触发 |
| 单召 | 以某个人格的身份直接应答 |
| 双人对谈 | 两个人格各自独立作答，主持人呈现**分歧在哪** |
| 圆桌 | 多个人格多轮互质，看到彼此发言再回应 |
| 遣将 | 分兵多路，各处理不同子问题后拼合 |
| **人格组（panel）** | 把一组人格 + 议题编排成可复用的圆桌配置 |
| 越用越准 | 记录使用中暴露的失败，回流给 蒸馏.skill 补缺口 |

## 铸的是双核：认知 + 人格

拘神铸的**不是一层，是同时铸两层**——缺任何一层，产物都不成立：

| 层 | 是什么 | 部件 | 决定 |
|----|--------|------|------|
| 🧠 **认知层** | 思维视角与认知框架 | 心智模型、决策启发式、Agentic Protocol 研究维度 | 他**怎么看**问题 |
| 🎭 **人格层** | 身份与表达 | 身份卡、表达DNA、反模式 | 他**是谁、怎么说** |

- **只有认知层** → 是一套方法论，不是一个人：没有「我」的立场，召不出来，对谈时退化成两份分析框架并排
- **只有人格层** → 是一个会说话的壳子：语气像，但看问题的方式和谁都一样，圆桌上给不出真正不同的视角
- **两层都在** → 才叫**人格运行体**：用那套认知看问题，并用那套方式说出来

诚实边界与防漂移机制是**运行层**，不参与这个二分——它们保证上面两层在长对话里不塌。

保真度评分卡也按这两层出分：**风格辨识度 <12/20（语气认不出来）单独判红线**，不会被认知层的高分掩盖。

## 工作流

```
入口分流 → 人格卡草案 → 素材就绪 → 铸人格（六件套）
        → 🔴人格卡确认 → 生成并安装 → 保真度验证 → 召唤 → 交付
```

## 人格三型

| 类型 | 是什么 | 素材要求 | 诚实边界重点 |
|------|--------|---------|------------|
| **真人型** `real` | 指向真实公众人物 | **必须有蒸馏档案** | 公开表达 vs 真实想法的差距 |
| **原型型** `archetype` | 领域专家原型（如「怀疑论 CFO」），**不指向任何具体个人** | 档案可选 | **必须声明是合成原型** |
| **虚构型** `fictional` | 小说/影视/游戏角色 | 原作设定 | 不复现原文；版权提示 |

## 召唤四阵型

| 阵型 | 人数 | 做什么 | 关键机制 |
|------|------|--------|---------|
| **单召** | 1 | 人格直接接管对话 | **不 spawn**——主 agent 直接演 |
| **双人对谈** | 2 | 各自独立作答，呈现分歧 | 并行 spawn，互不可见 |
| **圆桌** | 2-5 | 多轮互质 | 第 1 轮互不可见，第 2 轮注入他人发言 |
| **遣将** | 2-N | 分兵处理不同子问题后拼合 | 每人拿**不同**子问题 |

主持人的三条硬约束：**不扮演人格**、**防串味**（每个 agent 只读自己的人格文件）、**不调和分歧**（分歧就是产出）。

## 人格组（panel）

一组人格 + 议题编排，可复用：

```
蒸馏一下芒格、塔勒布、林奇 → 综合一下他们的分歧 → 开个圆桌
```

```bash
python3 scripts/panel_plan.py distilled/value-investing \
    --out ~/.claude/skills/panels/value-investing.panel.md
```

**panel 只给主持人读，绝不注入任何人格的 prompt。** 人格永远不知道自己「应该反对谁」。

两个理由都是硬约束：

- 预置「谁反对谁」会破坏 `summon-protocol.md` 的**独立首次**（圆桌第 1 轮必须互不可见，否则第一轮就被最强的人格带跑）
- 告诉人格「你反对 Y」属于**替人格表态**，它会为了配合编排去断言档案里没有的立场 →
  触发保真度评分卡的「**档案一致性 = 0 → 直接判 D**」红线

所以议程只用于**第 2 轮** seeding：第 1 轮照常盲测，第 2 轮才把真断层线作为「你们可能分歧的地方」注入。

## 目录结构

```
summon-skill/
├── SKILL.md                       # 主技能定义（流程、阵型、伦理红线、降级表）
├── README.md                      # 本文件
├── references/
│   ├── persona-forge.md           # 铸人格方法论（六件套、三型差异、防漂移）
│   ├── persona-template.md        # 人格 SKILL.md 模板
│   ├── summon-protocol.md         # 召唤协议（四阵型、spawn 模板、汇总格式）
│   ├── panel-format.md            # 人格组格式与编排（主持人侧，不注入人格）
│   ├── fidelity-scorecard.md      # 保真度评分卡（6 维，≥B 为可用门槛）
│   ├── adversarial-refine.md      # 对抗精炼（保真度/可用性攻击者）
│   └── roster-format.md           # 名册规范 + 漂移检测 + 使用反馈
├── scripts/
│   ├── forge_scaffold.py          # 读档案生成人格目录骨架 + 预填
│   ├── fidelity_check.py          # 人格静态质检（6 项）
│   ├── panel_plan.py              # 从综合档案生成 panel 骨架
│   ├── roster.py                  # 名册 + panel 校验 + 漂移/冲突检测
│   ├── feedback_log.py            # 记录使用反馈（写自己目录）
│   └── eval_record.py             # 保真度历史与对比
└── examples/
    └── skeptic-cfo-persona/       # 原型型人格完整示例
```

人格装在用户级 `~/.claude/skills/<slug>-persona/`，装完即可被 harness 触发。
人格组装在并列的 `~/.claude/skills/panels/`。

## 组合剧本：越用越准

```
① 蒸馏素材        → distilled/<slug>/DISTILLATE.md
② 铸成人格        → 读档案铸 *-persona
③ 使用中暴露失败  → feedback_log.py 写 FEEDBACK.jsonl（人格自己的目录）
④ 只读汇总反馈    → distill 的 feedback.py 找真缺口
⑤ 补素材、更新档案 → version++ ，档案哈希变
⑥ 重铸 + 验证     → roster 报 stale → 重铸 → eval_record.py compare 看是否真变好
```

**三点如实说明**：

- **忠实沉默不是缺陷**。拒答在 gaps 映射、结构性沉默、伦理红线场景下都是**正确行为**。
  把它记成缺陷会逼 distill 为刻意沉默的人编造立场——那正是评分卡判 0 分的行为。
  `faithful_silence` 单独统计，**不计入**缺陷汇总。
- **无证据不写入**。`feedback_log.py` 强制要求 `--evidence`（档案条目/行号/出处）。
  无出处的反馈是**意见**不是缺陷，铁律3 禁止据此行动。
- **不是全自动闭环**。写反馈**不会**触发漂移检测（它不改档案哈希）。
  需要用户跑一次 distill 的「补充蒸馏」，档案更新后哈希才变，roster 这时才报 stale。

```bash
npx skills add ai4next/summon-skill
```

## 使用

```
铸个「怀疑论 CFO」的人格
用芒格的视角看看这个决策
让塔勒布和芒格都说说这件事
开个圆桌，让他们互相质疑
分头看看这个方案：让 CFO 算账，让产品看体验
```
